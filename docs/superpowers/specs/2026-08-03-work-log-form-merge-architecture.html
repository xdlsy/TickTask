三个候选方案。主表单（顶部添加）所有方案一致；区别在 AI 拆条后的批量编辑列表。

问题：用户脑暴输入 → AI 拆出 N 条 → 每条需要用户补齐 日期/时段/活动/象限 才能入库。 这 N 条的批量编辑界面怎么设计？下面 3 个候选视觉差距明显，背后对应不同的组件复用策略。

主表单 · 所有方案一致

顶部"添加工作内容"表单。布局 C（卡片分组），必填 4 + 可选 4。所有方案的这部分完全相同，区别仅在下方 AI 批量列表。

AI 批量列表 · 三个候选

方案 1 · 推荐 每行复用主表单（统一一个组件）

AI 拆出的每条都呈现为主表单的复制品：完整布局 C，必填字段空着等用户填，可选字段已由 AI 预填。 顶部用一条 "AI 草稿 (2)" 标题分隔。一个 WorkItemForm.vue 用在三个位置：添加 / 批量 / 编辑。

优点

  • 一个组件三处复用，DRY
  • 添加和批量编辑视觉一致，用户认知负担低
  • 字段改动只需改一处

缺点

  • N 条草稿时整页很长，每条占用空间大
  • 主表单和批量列表视觉"重复"，分不出主次
  • 需要重构 3 个调用点
方案 2 每行紧凑卡片（必填优先 + 可选折叠）

批量列表每行紧凑：顶部一条必填字段横向排列（日期/活动/时段/象限/删除），下方一条窄窄的可选区横向 4 列展示 AI 已填内容（只读或点击展开编辑）。 视觉上"必填是任务，可选拆是上下文"。可独立组件 BatchItemRow.vue。

方案 3 表格式批量编辑（Excel 风）

把 N 条草稿展示成一张表，每行一条；列为 日期 / 时段 / 活动 / 象限 / 内容 / 问题 / 结果 / 影响。 必填列高亮、可选列稍淡。可独立组件 BatchTableEditor.vue。Excel 风批量编辑体验最熟。

编辑入口 · 三方案一致

TodayPanorama 表里点"编辑"时，三种方案的编辑入口行为相同：把主表单切换为编辑态（替换顶部添加表单），表单内 8 个字段全部回填。 保存后立即落库，回到添加态。这部分不需要再分方案。

交互流程： 今日全景表 → 点编辑 → 顶部"添加工作内容"表单变成"编辑工作内容"，所有字段回填 → 改完点保存 → 立即落库 → 回到添加态。
实现： WorkLog.vue 维护 editingItemId 状态（已有），三种方案都复用这个机制，无需新增组件。
说明：所有视觉使用项目设计令牌（FAF9F6 / FFFEFC / B8452C / Playfair Display / DM Sans）。 方案 1 视觉与主表单完全一致；方案 2 紧凑但仍卡片化；方案 3 表格式扫描效率最高但长文阅读差。 本文件仅供方案对比，非实际代码。
